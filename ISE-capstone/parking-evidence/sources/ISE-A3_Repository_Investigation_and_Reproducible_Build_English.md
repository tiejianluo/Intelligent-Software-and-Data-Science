# ISE-A3 | Repository Investigation and Reproducible Build

- Course：Intelligent Software Engineering
- Release：2026-10-19 16:30 (Asia/Shanghai)
- Deadline：2026-10-26 16:30 (Asia/Shanghai)
- Maximum：5
- Platform：https://learn.spaiq.ai

## Objective

Understand an unfamiliar repository through execution evidence and establish a safe change boundary.

## Required work

1. Freeze repository commit, dependencies, and runtime environment.
2. Record clean setup, build, test, and start commands.
3. Locate entry points, modules, persistence, external interfaces, configuration, and critical dependencies.
4. Reconstruct one end-to-end path and separate facts from inference.
5. Identify three risks; compare two responses to one in an ADR.

## Deliverables

- Stable commit/tag and repository URL
- Reproduction guide and environment lock
- Architecture/call-path map
- Risk register
- ADR and execution evidence

## Platform submission

In the matching learn.spaiq.ai task, submit a 150–300 word result summary and a stable GitHub repository URL with commit/tag. Keep notebook, PDF, source, raw results, and AI-use log in that versioned repository. Screenshots or demos do not replace code, provenance, or reproduction instructions.

## Common requirements

- Executable top-to-bottom; freeze seeds, dependencies, data version, and environment.
- Retain failed runs, negative results, and evidence that challenges the claim.
- Disclose AI tool/task, accepted and rejected advice, and independent verification.
- Do not fabricate data, sources, experiments, users, execution, or results; never expose credentials or personal data.

## Five-point rubric

- Problem, context, and method choice: 1.25
- Execution, artifact quality, and reproducibility: 1.50
- Analysis, counterexample, and limits: 1.25
- Communication, reflection, and AI verification: 1.00
